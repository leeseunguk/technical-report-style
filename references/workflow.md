# 제작과 검증 절차

## 입력과 작업 분리

별도 작업 폴더에 원고 JSON, 그림, 그림 장부, 검증 기록, 새 DOCX,
PDF, 페이지 PNG를 둔다. 원본 DOCX·PDF·데이터는 읽기 전용 입력이다.
실행 예제의 경로는 현재 워크스테이션 기준이며 이동 시 명시적으로 바꾼다.

새 문서의 기본 실행은 동봉 템플릿과 예제만으로 가능해야 한다.
과거 GSR/QTN 문서나 캐시는 서식의 유래이지 실행 의존성이 아니다.
사용자가 논문 그림을 요구하지 않았고 주제에도 논문 근거가 없으면
아래 논문 그림 절차는 적용하지 않는다. 논문 그림을 명시적으로 요구했다면
먼저 관련 원전을 찾는다. 찾지 못했다는 사실을 임의 면제 사유로 쓰지 않는다.
공식 기술 문서·실험 데이터·작성자 설명은 각각의 출처 유형으로 다룬다.

new에서는 기존 본문·그림·각주·머리말의 주제 내용이 따라오지 않게 한다.
append에서는 원본 본문 순서·표·미디어·스타일·section 설정을 보존한다.
한 모드의 검증을 다른 모드의 보증으로 쓰지 않는다.

## 집필 전 요구·시각 자료 계획

작업 폴더에 `report-plan.md`를 작성한다. 특정 주제의 번호나 수치를
복사하지 말고 이번 요청의 실제 내용을 아래 구조로 채운다.

| 요구 ID | 사용자 요구와 필수 여부 | 원고 절 | 완료 증거 | 상태 |
|---|---|---|---|---|

| 절 | 핵심 개념·과정·비교 | 계획 그림 ID | 종류·설명 목적 | 출처/제작 방법 | 글만 남기는 이유 |
|---|---|---|---|---|---|

본문 초안을 쓰기 전에 주요 항목의 시각화 계획을 채운다. 그림이 많은
문서를 요청했다면 주요 원리·메커니즘·과정·변경 전후 비교마다 대응
시각 자료가 있는지 확인한다. 한 그림이 여러 개념을 설명하면 그 관계를
명시한다. 그림 수만 늘리는 중복·장식은 충족 증거가 아니다.

계획한 논문 그림·개념도·결과 그림의 개수를 합계로 기록한다. 최종
개수와 다르면 이유를 남기고 주요 항목이 누락되지 않았는지 다시 본다.
명시적 요구의 생략은 설명을 적었다는 이유만으로 완료 처리하지 않는다.
새로 설명하는 중요한 메커니즘은 대응 그림이 있어야 한다. 멀리 있는
기존 그림 하나나 장식 그림은 그 그림이 아니다. 각 그림의 설명 목적,
가까운 본문 해설, 캡션, 출처를 계획에 연결한다.
번호 있는 식과 핵심 수치의 출처도 같은 계획에 적는다. 최종 대조는
출처 장부에서 한다.

사용자가 원고 진단이나 자동 윤문을 명시적으로 면제하면 계획에 예외를
적는다. 실행하지 않은 진단·윤문·자동 문장 검사를 완료 증거로 넣지 않는다.
과학·수식·출처 장부·렌더 검사는 예외 표의 유지 검사에 남긴다.

| 예외 | 사용자 지시 문장 | 건너뛴 단계 | 유지한 검사 | 날짜 |
|---|---|---|---|---|

## 인포그래픽 제작과 확인

개념 인포그래픽만 Astra native imagegen으로 만든다. 논문 원본 캡처,
데이터로 그린 결과 그림, 문서 수식에는 imagegen을 쓰지 않는다.
Grok 이미지 생성으로 개념도를 만들지 않는다.

1. 리드가 그림의 설명 목적, 구성 요소, 화살표 의미, 단위, 대안 관계,
   대응 본문과 근거를 설계한다. 새로 도입하는 중요한 메커니즘은
   그 메커니즘을 보여 주는 그림이 있어야 한다. 멀리 있는 기존 그림
   하나나 장식 그림은 대응 그림이 아니다.
2. 리드가 설계의 물리·논리적 오류와 누락을 근거와 대조해 고친 뒤 생성한다.
3. Astra native imagegen으로 실제 이미지를 만든다. 파일 존재와
   실제 그림을 확인한다.
4. 리드가 만들어진 이미지 자체를 열어 설계·본문과 대조한다. 생성 결과가
   올바른 설계를 잘못 그린 경우도 수정 대상이다. 별도 Astra 독립 검토는
   필수가 아니다.
5. 설계 버전, 이미지 경로·해시, 생성 도구, 확인·수정 내역을 그림 장부에
   연결한다. 수정 뒤에는 수정된 그림을 다시 연다.

정기 집필은 리드, 정기 구현은 Grok 4.7 xhigh다. fast 모델은 쓰지 않는다.
상위 사용자 지시가 바뀌면 최신 지시를 따른다. 검토자의 읽기·판정과
제작자의 수정을 분리한다. 개념 인포그래픽의 이미지 생성은 구현 역할이 아니다.

## 그림 장부

그림마다 다음을 기록한다.

| 공통 | 내용 |
|---|---|
| 식별 | 그림 ID, 원고 위치, 파일 경로, SHA256 |
| 분류 | 논문 원본 / 개념도 / 실제 결과 |
| 설명 | 캡션, 본문에서 읽는 법을 설명한 위치 |
| 근거 | 논문·데이터 참조 번호, DOI/URL 또는 산출물 경로 |
| 최종 배치 | 실제 PDF 페이지 번호 |
| 계획·검토 연결 | 요구 ID, 계획한 개념, 설명 목적, 설계/이미지 검토 버전, 생성 도구, 검토자와 생성자의 분리, 지적 처리 |

논문 원본이면 원본 PDF 해시, 물리 페이지와 인쇄 페이지,
hybrid 실행 명령·버전·로그·출력 JSON, 검출 블록 ID/상자,
좌표계, 최종 crop 상자, 여백·확장 이유, DPI를 추가한다.
상자 숫자만 있거나 실행하지 않은 명령이 적혀 있는 것은 hybrid 실행 증거가 아니다.
도구 실패나 fallback이 있으면 실제 범위를 그대로 쓴다.

개념도이면 설계 의도와 “실측 아님” 표시를 넣는다. 대안 A/B는
연쇄 연결처럼 그리지 않는다. 실제 결과이면 데이터 필드·단위·분모·
변환을 기록하고 선·점·범례 수치를 원본 배열과 대조한다.

## 원고 검사

각 그림의 ID가 바로 앞 본문과 캡션에 존재해야 한다. 단순 언급뿐 아니라
축·선·비교에서 무엇을 읽어야 하는지 문장으로 설명한다. 그림 번호는
문서 전체에서 연속이며 장마다 다시 시작하지 않는다.
참고문헌은 본문 인용과 항목이 정확히 같다. 인용한 문헌마다 완전 서지가
있고, 인용하지 않은 항목은 제목을 단 더 읽을거리 목록이 아니면 두지 않는다.
기본은 저자-연도 본문과 AGU 완전 서지다.
번호 인용은 원고가 `numbered`를 명시할 때만 검사한다. 저자·연도·DOI·데이터 제품명을 확인한다.
번호 있는 식·그림·표와 핵심 수치는 사용 지점의 출처가 있다. 최종 조판 전에
아래 출처 장부로 대조한다. 문장에 다는 방법은 SKILL.md를 따른다.
모든 수식에는 가까운 본문 문단이 뜻, 물리 메커니즘, 기호와 단위,
적용 범위, 확인 가능한 출처를 쉬운 문장으로 말한다. 순서는 용어, 쉬운 정의, 그 양이
식의 어디에 들어가는지, 그래서 무엇이 달라지는지다. 식 번호, 기호 목록,
캡션, 용어 나열만 있으면 미완료다.
이미 정의한 기호를 문장 안에서 다시 부를 때는 정의를 반복하지 않는다.
문서 수식은 편집 가능한 네이티브 OMML이어야 한다. 필수 입력 `eq.lines`와
선택 입력 `eq.latex`는 문자열 목록이며, `latex`를 주면 줄 수가 같아야 한다.
분수·근호·첨자·지수·합·적분에는 `latex`를 함께 주고 변환 후 실제 구조를 확인한다.
단순 선형식의 `lines`만 입력은 네이티브 문자로 보존한다. OMML 없이 평문만
출력하거나 복잡한 식을 단일 문자 노드에 넣고 구조화됐다고 말하면 미완료다.
기본은 `python3 scripts/check_prose.py 원고.json`으로 문법 오류와 반복 문단을 검사하고,
경고가 나오면 [다시 쓰기 교훈](writing-lessons.md)의 해당 항목으로 원고를 고치는 것이다.
사용자가 원고 진단과 자동 윤문을 명시적으로 면제하면 자동 문장 검사는 돌리지 않는다.
면제 사실만 계획에 적고, 검사를 실행한 것처럼 쓰지 않는다. 과학·수식·출처 장부·렌더 검사는 그대로 한다.
원문 스캔의 소수점이나 기호가 흐리면 원본을 대조한 숫자 해설을
편집 가능한 본문에 넣고 원본 곡선을 덧칠하지 않는다. 캡처 그림 안의 식은
이미지로 둔다.

## 출처 장부

최종 조판 전에 번호 있는 식, 그림, 표, 결론에 쓰는 핵심 수치와 주장마다
한 줄을 만든다. 윤문으로 출처 문장이 바뀌면 장부를 다시 맞춘다. 원고 진단이나
자동 윤문 면제는 이 장부를 면제하지 않는다. 출처를 문장에 다는 방법은
SKILL.md의 사용 지점 규칙을 따른다. 고정 표지 열은 만들지 않는다.

| 항목 | 원고 위치 | 주장한 출처 | 대조한 원본 | 상태 |
|---|---|---|---|---|

- 항목은 식 번호, 그림·표 번호, 또는 핵심 수치다.
- 원고 위치는 절과 문장 또는 캡션이다.
- 주장한 출처는 본문에 단 문장이다. 저자-연도와 원문 식·그림·표·절·쪽,
  또는 파일·필드·코드 경로와 함수가 그 문장 안에 있다. 문헌이 뒷받침하는
  부분과 이 문서에서 한 일이 그 문장에서 구분된다.
- 대조한 원본은 연 PDF의 쪽과 식 번호, 또는 연 파일과 필드다. 확인하지
  않았으면 비운다. 없는 식 번호나 쪽을 만들지 않는다.
- 상태는 확인, 고쳐 쓴 뒤 확인, 미확인 중 하나다. 미확인을 확인으로 올리지
  않는다.

집필자가 아닌 검토자가 장부를 원본 PDF와 파일에 대조한다. 리드가 장부를
만들 수 있지만, 자신의 대조만으로 독립 검토를 대신하지 않는다. 독립
검토가 없으면 상태를 확인으로 올리지 않는다. 코드만 있고 그 코드가
구현한 물리 출처가 없으면 미완료다.

그림의 캡처 상자와 해시는 그림 장부에 둔다. 출처 장부는 그 행을 가리키고,
대조 상태와 원문 위치만 다시 적는다.

## 렌더와 검증

최종 조판은 출처 장부의 독립 대조 뒤에 한다. 미확인 항목이 본문에서
확인된 것처럼 보이면 조판하지 않는다.

1. 내용·수치·그림·수식 검증 후, 사용자가 자동 윤문을 명시적으로
   면제하지 않았다면 [im-not-ai 최종 윤문](polishing.md)을 수행한다.
   면제했다면 그 문장과 날짜를 `report-plan.md`에 적고 진단·윤문·자동 문장
   검사를 실행했다고 쓰지 않는다. 과학·수식·출처 장부·렌더 검사는 어느 경우에도
   빼지 않는다. 출처 장부 대조가 끝난 뒤, 보존 검사와 윤문 게이트를
   통과한 원고 또는 면제가 기록된 원고를 CLI에 넣어 새 DOCX와 감사 기록을 만든다. CLI는 수식 뒤 본문 해설, 식·표·그림 출처의 본문 등장, `--ledger`가 있을 때 장부 항목과 파일 존재를 검사한다. 인용된 쪽·식 번호가 원문과 맞는지는 검사하지 않으며 검토자가 대조한다. 입력 SHA256과
   실패 시 출력 상태를 확인한다.
2. Word 또는 설치된 LibreOffice로 PDF를 만든다. 원본과 독립 프로필을 사용하고
   기존 PDF를 덮지 않는다. 렌더러 버전과 글꼴 환경을 적는다.
3. 실제 PDF의 모든 페이지를 150 dpi PNG로 만든다. 페이지 수·크기·해시를 기록한다.
4. 모든 이미지를 직접 열어 제목, 표, 그림, 축·범례, 캡션, 본문,
   한글 글리프, 잘림과 겹침을 확인한다. 텍스트 추출만으로 시각 검사를 대신하지 않는다.
5. append라면 같은 렌더 환경에서 원본 페이지의 픽셀·텍스트를 대조한다.
   기존 결함은 별도 기록한다. 허용하지 않은 원본 변화는 실패다.
6. 인포그래픽 설계·실제 이미지의 확인 기록을 본다. 사용자가
   전체 독립 검토를 요구했다면 리드와 일반 Astra가 최종 산출물 전체를
   독립 검증한다. 고친 뒤 변경 페이지를 다시 보고 전체 페이지 목록의
   신선도를 확인한다. 윤문으로 그림 설명 의미가 바뀌면 해당 검토도 다시 한다.
7. 요구별 완료 증거와 계획 대비 그림 수·핵심 개념의 시각화 여부,
   윤문 기록 또는 명시적 면제 기록, 출처 장부와 독립 대조 상태,
   최종 DOCX/PDF 해시·그림 배치 장부를
   연결해 납품한다. 충족하지 않은 명시적 요구, 미해결 지적, 기록 없는
   윤문 생략, 출처 장부 없는 조판, 미확인을 확인으로 적은 기록이 있으면
   완료로 표시하지 않는다.

기계 검사 성공은 전체 과학 검증 성공이 아니다. Word XML에서 텍스트·표가
편집 가능함을 확인한 것은 Word GUI에서 직접 편집해 본 것과 다르다.

## 렌더러 선택

기본적으로 해당 환경에 설치된 Word 또는 LibreOffice를 사용한다.
실제 사용한 버전·글꼴을 기록하고 깨끗한 출력 폴더에 PDF를 만든다.
기존 프로젝트의 특정 렌더 스크립트가 있어야만 동작하는 설계로 만들지 않는다.

### 현재 워크스테이션에서 선택 가능한 기존 경로

기존 문서 제작 폴더:
`/mnt/c/Users/user/Documents/Private/GSR/gs_fast/artifacts/qtn_temperature_chapter_20261003`

이 폴더의 `render_pdf_local.sh INPUT.docx NEW_OUTPUT_DIRECTORY`는
사용자 로컬 LibreOffice 26.8.1.1과 Windows 글꼴을 사용하는 검증된 경로다.
실행 전에 파일과 의존 경로가 있는지 확인한다. 다른 환경에 그대로
복사해도 작동한다고 가정하지 않는다. 현재 환경의 Word COM 실행은
과거에 `0x80080005`로 실패했으므로 이 경로의 결과를 Word 검수라고 쓰지 않는다.

장기 실행은 부모 소유 monitor로 시작한다. 완료 로그와 종료코드 0을
확인한 다음 실제 PDF를 연다. 실패한 실행을 조용히 재시도하거나
미리 만들어 둔 PDF를 새 결과로 제시하지 않는다.
