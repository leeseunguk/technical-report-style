# 마지막 집필 단계: im-not-ai 윤문

내용·근거·그림이 확정되면 기본 마지막 문장 다듬기는 **im-not-ai의
실제 `humanize-korean` 스킬**이다. 일반적인 자체 윤문을 이
스킬 실행이라고 부르지 않는다. 윤문을 했으면 조판과 전 페이지 검수를 한다.

사용자가 이번 작업에 대해 원고 진단 또는 자동 윤문을 명시적으로 면제하면
그 지시가 이 기본보다 우선한다. 면제한 문장, 건너뛴 단계, 날짜를
`report-plan.md`에 적는다. 실행하지 않은 진단, 게이트, `check_prose.py`를
실행했다고 쓰지 않는다. 진단과 자동 윤문을 함께 면제하면 자동 `check_prose.py`도
돌리지 않는다. 과학 검증, 수식의 뜻·단위·적용 범위, 렌더와
전 페이지 검수는 이 면제로 끄지 않는다. 명시적 면제가 없으면 아래를
생략하지 않는다.

## 실제 스킬과 버전

- 원본: https://github.com/epoko77-ai/im-not-ai
- 사용 정의: `codex/skills/humanize-korean/SKILL.md`
- 확인한 리비전: `2f3d943d08056b612a92e12bfb72ea94dd2acd18`
- 현재 설치 진입점: `~/.omo/agent/skills/humanize-korean/SKILL.md`
- 원본 체크아웃: `~/.local/share/im-not-ai/`

스킬을 실행할 때 위 진입점의 실제 파일과 지시된 참조 파일을 읽는다.
심링크의 물리 경로를 기준으로 `SKILL_ROOT`를 구하며 현재 작업 디렉터리에서
경로를 추측하지 않는다. 다른 환경에서는 완전한 원본 스킬과 리소스를
설치한 뒤 진행한다. 이 보고서 스킬 ZIP은 외부 윤문 저장소 자체를 포함하지 않는다.
리소스가 없거나 실행에 실패하면 미완료로 기록하며 조용히 생략하지 않는다.

## 보고서 연결

1. 윤문 전 원고를 보존하고 문단/캡션 ID와 텍스트의 대응표를 둔다.
   append에서는 새로 작성한 내용만 대상으로 하며 보존 대상 원본은 건드리지 않는다.
2. 장르는 `report`로 설정한다. 본문과 캡션의 설명 문장은 윤문하되
   수치·단위·날짜·고유명사·수식·표 데이터·그림 ID·출처·저자-연도 인용·인용 번호·DOI/URL·
   직접 인용은 보호한다. 한계·불확실성·부정 표현의 의미를 약화하지 않는다.
3. 원본 스킬의 `prepare_monolith_input.py`로 입력을 준비하고 `route_hint`에
   따른 light/standard/heavy 경로를 실행한다. light는 호출 단계의 이름이지
   fast 모델 사용 허가가 아니다. 사용자가 정밀 모드를 지정하면 원본 규칙을 따른다.
4. 역할별 원본 파일을 읽고 실행한다. 이 역할은 문장 작업이다. 면제가 없을 때
   진단·윤문·국소 수정은 Grok 4.7 xhigh, 읽기 전용 독립 검토는 일반 Astra다.
   원본 finalizer 역할이 글을 수정하는 부분도 제작자에게 맡긴다. 개념 인포그래픽
   생성은 Astra native imagegen만 쓰고 Grok 이미지 생성을 쓰지 않는다.
   런타임별 도구 이름은 실제 제공 도구에 맞춘다. 면제가 없으면 진단·재조립·검증
   단계를 생략하지 않는다. 사용자가 진단과 자동 윤문을 면제했다면 이 단계를
   실행하지 않는다. 생략을 완료로 적지 않고 계획의 예외 기록만 남긴다.
5. 원본 `verify_gates.py`를 실행하고 원문·윤문본·변경률·종료코드·진단·
   finalize 결과를 보존한다. 원본 정의의 exit 0은 통과, 1은 경고 처리와
   finalize, 2는 채택 금지, 3은 실행 오류다. 적용 버전의 원문 지시를 확인하고
   요구되는 후속 검사까지 끝낸다. 경고나 hold 상태를 정상 완료로 바꾸지 않는다.
6. 윤문을 실제로 한 경우에만 이 검사를 한다. 원본 게이트는 변경률·수치·서법을 보지만 문법은 보지 않는다. 윤문 전후 원고에 `scripts/check_prose.py`를 실행하고, 윤문 뒤에 새로 생긴 오류(예: 빼는다, 쓰는다)가 있으면 그 수정은 채택하지 않는다. 사용자가 진단과 자동 윤문을 면제했다면 이 검사를 돌리지 않고, 돌렸다고 쓰지 않는다.
7. 스킬 게이트와 별도로 리드가 보호 항목과 의미를 원고 ID별로 대조한다.
   전문 용어·수치·그림 해설을 문장 자연스러움을 이유로 삭제하거나 바꾸지 않는다.
   의미 변화가 있으면 해당 수정은 채택하지 않고 바로잡는다.
8. 채택한 설명 문장만 같은 ID의 원고 블록에 반영한다. JSON 구조·그림 연결·
   표·수식·서지 필드는 유지한다. `HUMANIZE-SUMMARY` 같은 윤문 도구의 감사용
   메타데이터는 별도 기록에 남기고 보고서 본문으로 싣지 않는다.
9. 윤문본으로 DOCX/PDF를 새로 만들고 전체 페이지를 연다. 문장 길이가 바뀌며
   캡션·표·페이지 나눔이 달라질 수 있으므로 윤문 전 렌더를 최종 증거로 쓰지 않는다.

완료 기록에는 사용한 원본 스킬 경로·리비전, 실행 경로, 입력/출력 파일,
게이트 실제 결과, 보호 항목 대조, 최종 렌더를 연결한다. “이미 좋은 글”로
수정이 거의 없어도 실제 진단·게이트 결과를 남긴다. 임의 변경률을 만들지 않는다.
